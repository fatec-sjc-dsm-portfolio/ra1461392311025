Sistema de análise de dados relacionados à Covid Longa

O primeiro projeto criado por nós tinha um foco na coleta e processamento de dados do Covid-19 e como ele impactava vítimas á longo prazo. Fizemos isso criando um site que permitisse que o usuário visualizasse os dados de sintomas que pudessem ou não serem relacionados á chamada de "covid longa", série de sintomas que persistem mesmo depois do fim do ciclo da doença.


O método usado foi o da raspagem de dados, á partir dos dados do site de saúde pública TabNet, que disponibiliza dados de saúde pública do Brasil. O alvo das análises foram cidades do vale do Paraíba, região onde a faculdade se encontra.


Foram utilizadas várias tecnologias nesse primeiro projeto, como HTML, CSS, e React para a construção da página, e Python para a realização da raspagem de dados. Também foi utilizado o Github para a organização do projeto, e o Figma para a geração do wireframe.

Better Call Us - Sistema de chamadas de serviço

O segundo projeto desenvolvido, depois de uma necessária troca de equipe, foi o Better Call Us, um sistema de chamadas de serviço. O projeto tinha três frentes diferentes:

O usuário, que tinha o poder de solicitar uma chamada para um suporte, fosse ela para fazer uma pergunta, requisitar uma manutenção, ou fazer uma reclamação.

O suporte, que tinha o poder de aceitar ou recusar a chamada, e, caso aceitasse, poderia conversar com o usuário através de mensagens que funcionavam como emails. Ele poderia visualizar todas as chamadas em aberto ou em pendência e associar uma delas á si mesmo.

E o administrador, que tinha o poder de criar, editar e deletar usuários e suportes, além de poder visualizar todas as chamadas em aberto, pendentes e fechadas, podendo assim fazer a manutenção dos status, suportes e mensagens.


O projeto também contava com uma página de perguntas frequentes, onde, como uma página de ajuda, o usuário poderia encontrar respostas para perguntas comuns. Essa página continha várias sessões diferentes com perguntas abrangentes, e o usuário poderia clicar em uma pergunta para ver a resposta ou instruções se necessário.

Foram utilizadas várias tecnologias novas e recorrentes, como o CSS e HTML para a criação da estrutura web do site, o mySql para a criação do banco de dados que contém as perguntas, mensagens, clientes, suportes e etc., o Node.js e o Spring para a criação da aplicação, O react para a implementação online do Typescript, o Figma para a criação do wireframe e o Github para a organização.

Minhas contribuições ao projeto:

Minha principal contribuição ao projeto foi a criação do front-end, que foi feito em HTML e CSS, e a criação do design do site, que foi feito no Figma. Esse projeto envolvia bem mais telas distintas que o projeto anterior, então gerir o front-end dele foi bem mais trabalhoso.


Também comecei a me familizarizar com o Typescript, utilizado como base principal do projeto. Eu não tive muito envolvimento com o backend, mas para a implementação do front-end, tivemos que migrar a produção do site do HTML para o Typescript. Mesmo que não tenha me envolvido com o sistema do banco de dados, mas pude ver como ele foi feito e como ele se comunicava com o front-end, o que foi uma experiência muito valiosa.

SGA - Sistema de Gerenciamento de Ativos

O terceiro e mais recente projeto desenvolvido, o SGA se trata de um projeto muito útil e expansivo: Manter o controle de todo um sistema que permita que o administrador manipule e tenha informação completa sobre todos os ativos de sua empresa de forma organizada e ágil.

O projeto foi dividido em duas frentes diferentes:

O administrador, que tinha o poder de criar, editar e deletar ativos e membros do time, além de poder visualizar todos os ativos em uso ou estado de manutenção. Além disso, ele poderia marcar quais ativos estão sendo utilizados por qual usuário.

E o usuário, que tinha o poder de alterar o estado de ativos que tivessem sido designados a ele.


O projeto também continha um sistema de gráficos com uma relação de custo e uso de cada ativo, reçacionando custos de uso e manutenção.

Além disso, o projeto também continha um sistema de notificações, que notificava o usuário quando um ativo estava prestes a sair do estado de manutenção, ou quando um ativo estava sendo utilizado por outro usuário.


Nesse projeto, houve uma estipulação extra: Ele deveria ser feito no estilo single-page application, ou seja, uma página que funciona completamente na mesma rota.

Foram utilizadas várias tecnologias novas e tecnologias antes exploradas só que com mais aprofundamento, como o Typescript e o CSS para a criação do frontend da página, o mySql para a criação do banco de dados que contém os ativos e usuários, além dos preços para os gráficos, o Node.js e o Spring para a criação da aplicação, O react para a implementação online do Typescript, o Java para a criação da lógica do backend, o Figma para a criação do wireframe e o Github para a organização.

Minhas contribuições ao projeto:

Minha principal contribuição ao projeto foram contribuições do front-end do projeto, que dessa vez eram bem mais complexas em relação ao anterior. Meteorological Data Collector

O Meteorological Data Collector foi desenvolvido para coletar, exibir e gerenciar dados meteorológicos em uma interface simples e intuitiva. Além disso, o projeto inclui um sistema de ensino básico, focado em introduzir conceitos matemáticos relacionados à meteorologia, como média aritmética, regra de três e gráficos.


O sistema exibe informações meteorológicas em tempo real, como temperatura, umidade e velocidade do vento, extraídas de uma API externa. Esses dados são organizados em gráficos e tabelas para fácil análise. Já a parte educacional conta com módulos interativos para aprendizado, com exercícios práticos e material didático diretamente relacionados aos dados meteorológicos apresentados.


Para a implementação do projeto, utilizamos tecnologias como React e TypeScript no front-end, Node.js para a criação da API do sistema, e Docker para containerização e deploy. O Google Cloud foi usado como infraestrutura para hospedar e escalar a aplicação. Também fiquei responsável pelo sistema de educação necessário para a página.

Projeto final:

Minhas contribuições ao projeto:

Minha principal responsabilidade foi o desenvolvimento completo do front-end, do sistema educacional e da integração com APIs externas para captura de dados meteorológicos em tempo real. Trabalhei na coleta, normalização e pré-processamento dos dados recebidos, criei componentes reutilizáveis para as visualizações (gráficos de séries temporais, histogramas e mapas de calor) e implementei módulos interativos de ensino que explicam conceitos matemáticos usados nas análises.

No front-end, priorizei performance e acessibilidade: buffers e debounce foram usados para chamadas à API; lazy-loading em componentes gráficos reduziu o consumo de memória; e as visualizações foram desenhadas com atenção à leitura por cores e suporte a leitores de tela. Também colaborei na criação do wireframe e prototipagem no Figma, definindo fluxos de usuário e interações didáticas.

No backend e infraestrutura, participei da definição das rotas da API que expunham dados agregados, além de criar Dockerfiles para ambientes de desenvolvimento e produção e configurar pipelines básicas de CI/CD para deploy no Google Cloud.


Aprendizados:

Técnicos:

  • Desenvolvimento de aplicações data-driven com React e TypeScript, incluindo componentes de visualização reutilizáveis
  • Integração e normalização de dados de APIs em tempo real, tratamento de latência e erros
  • Criação de gráficos interativos e técnicas de visualização para dados meteorológicos
  • Docker, criação de imagens e deploy em Google Cloud com pipelines simples de CI/CD
  • Prototipagem e validação de UX com Figma para fluxos educacionais

Comportamentais:

O projeto reforçou práticas de documentação, planejamento e comunicação entre equipes multidisciplinares; melhorou minha capacidade de traduzir requisitos científicos em interfaces didáticas; e aumentou minha experiência em dividir trabalho em entregáveis testáveis para integração contínua.

Plataforma de Criação e Gerenciamento de Agentes de IA

O quinto projeto teve como foco resolver um problema comum em empresas de tecnologia: a dificuldade de centralizar e distribuir conhecimento sobre seus próprios sistemas, processos internos e regras de negócio. A solução proposta foi a criação de uma plataforma que permite o desenvolvimento e gerenciamento de múltiplos agentes de Inteligência Artificial, cada um com um conjunto específico de conhecimentos sobre áreas distintas da empresa.


Além disso, o sistema conta com um esquema de permissões: cada usuário tem acesso apenas aos agentes autorizados pelo administrador, garantindo organização e segurança na distribuição das informações.

Projeto final:

Minhas contribuições ao projeto:

Neste projeto, atuei como principal responsável pelo desenvolvimento do front-end mobile. Criei as telas, fluxos e interações do aplicativo com foco na experiência do usuário, acessibilidade e eficiência em redes móveis. Trabalhei com React Native e TypeScript para implementar o chat inteligente, lidando com eventos em tempo real, reconexão automática e otimização do consumo de dados em conexões lentas.

Implementei a camada de sincronização com os agentes de IA via WebSocket, incluindo mecanismos de enfileiramento de mensagens, confirmação de entrega e tratamento de conflitos em mensagens offline. Também projetei e integrei a lógica de permissões que controla o acesso a agentes específicos, garantindo que usuários só possam invocar agentes autorizados por suas roles.

Além do front-end, participei das decisões de arquitetura que impactaram o backend (endpoints, contratos de mensagens e autenticação), e implementei testes end-to-end para fluxos críticos do chat e permissões.


Aprendizados:

Técnicos:

  • Desenvolvimento mobile com React Native e TypeScript: boas práticas para performance e consumo de dados
  • Integração de chats em tempo real com WebSocket: reconexão, filas e confirmação de entrega
  • Design e implementação de sistemas de permissões e controle de acesso
  • Testes end-to-end e integração contínua para fluxos críticos
  • Práticas de deploy com Docker e Google Cloud

Comportamentais:

Assumi maior autonomia técnica, melhorei comunicação entre equipes e refinei a definição de requisitos para fluxos complexos, aprendendo a mapear casos de borda e priorizar entregas que reduzem risco para o produto.

Stratos — Plataforma ASG para análise territorial

O projeto Stratos é uma plataforma inteligente de análise territorial para propriedades rurais no estado de São Paulo, integrando dados públicos geoespaciais e permitindo consultas via mapa e linguagem natural. O foco principal é apoiar a tomada de decisão, fiscalização e análise de risco ambiental com respostas rápidas, visuais e rastreáveis.


O problema central era a dificuldade de cruzar informações dispersas de diferentes fontes públicas, como SICAR, INPE, ICMBio, FUNAI, INCRA e FCP, em uma interface unificada. Essa limitação prejudicava tanto a rastreabilidade dos dados quanto a agilidade na análise de áreas rurais, especialmente quando era necessário entender sobreposição com áreas protegidas, alertas ambientais e contexto regulatório.


A proposta de solução foi criar uma plataforma que combina análise ASG, visualização em mapa interativo e respostas baseadas em linguagem natural. O objetivo foi transformar dados técnicos e geoespaciais em uma experiência mais compreensível para analistas, gestores e usuários que precisam interpretar o cenário com rapidez e confiança.


Durante o desenvolvimento, trabalhei especialmente no processamento de dados com Bag of Words, além do design do frontend e das principais features de experiência do usuário, como busca, navegação, clareza visual, leitura de informações e usabilidade da interface. Nesse projeto, percebi como a forma como os dados são apresentados influencia diretamente a capacidade de análise e tomada de decisão.

Projeto final:

Minhas contribuições ao projeto:

Minha principal participação foi no desenvolvimento do fluxo de busca e análise textual com Bag of Words, além de cuidar do frontend e da experiência do usuário. Contribuí com a estrutura visual, organização das telas, navegação, hierarquia de informações e refinamento da interface para tornar o sistema mais intuitivo, claro e eficiente para o usuário final.


Também fiquei responsável por ajudar a transformar requisitos técnicos em elementos visuais e interativos, como telas de busca, leitura de dados e apresentação das respostas. Esse trabalho exigiu equilíbrio entre funcionalidade, estética e clareza, pois o usuário precisava compreender rapidamente o que estava sendo analisado sem perder contexto.


Além disso, participei da melhoria contínua da usabilidade, pensando em como apresentar informações complexas de forma mais direta, com foco em experiência, acessibilidade e fluidez no uso da plataforma.
